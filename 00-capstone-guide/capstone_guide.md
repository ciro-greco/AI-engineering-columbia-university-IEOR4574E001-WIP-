# Capstone Project Guidelines

*(Demo Day: December 6)*

## Goal

Build a small, functional AI application. Examples include a RAG system, a task-specific assistant, or another focused AI feature.
Select a real problem and scope it as an MVP suitable for a startup prototype or an internal engineering proposal.
You may choose any domain. The final submission must be a GitHub repository.

## Team Formation

Teams are created in class. Each team must have **3 to 5 members**.

## Project Selection and Proposal

* Each team selects and scopes its project within the first three weeks.
* **Proposal deadline:** End of Week 3.
* Proposal length: 1 to 2 pages containing the problem statement, intended users, and an initial description of MVP features.


## Deliverables

**All deliverables are due by Demo Day on December 6.**

### 1. Working Prototype

A repository or deployed application that instructors can run easily.
You must provide a reproducible execution environment. Options include:

* A Docker container
* Clear local setup instructions (requirements.txt, Makefile, environment setup, etc...)

### 2. Product Brief (approximately 2 pages)

A final written overview including the problem, the approach, the system architecture, and key lessons learned. 
You may revise and extend your Week 3 proposal.

### 3. Presentation Deck

This deck is used during the final exam. It should ideally include:

* The problem
* The proposed solution
* The full product vision (features you would build with more time and resources)
* The demo narrative
  The demo narrative should follow a user story that illustrates the before and after experience. The demo itself must reflect the actual prototype in your repository and must run end to end.
* A technical diagram of the demo application.

### 4. Demo Video

A short screencast (3 to 5 minutes) used as a fallback if the live demo fails.

### 5. Technical Appendix (optional but encouraged)

Include model choices, data sources, prompt strategies, evaluation methods, and important engineering decisions.

## Demo Day

Each team presents a live demo and short presentation.
Plan for a maximum **7-minute** presentation followed by **up to 10 minutes** of discussion.
All team members are encouraged to participate in the presentation or the demo.

## Grading Rubric

The capstone counts for **60 percent** of the course grade.

- **Functionality and Reliability (30%)**
Does the MVP solve the stated problem? Does it run reliably?

- **Technical Approach and Rigor (30%)**
Are the model choices, data handling, retrieval design, prompt design, and evaluation methods sound?

- **Product Thinking and User Experience (30%)**
Is there a clear user story? Is the scope reasonable? Does the prototype make sense for the intended user?

- **Communication and Teamwork (10%)**
Quality of the proposal, demo, and written materials. Evidence of collaborative work and clear role distribution.
